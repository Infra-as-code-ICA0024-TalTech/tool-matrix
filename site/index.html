About the criteria and tool inventory

The slide supplies the labels and the three anchor profiles but no written rubric. The other tools were rated on 17 November 2026 using these readings of the labels, calibrated so the slide's own scores stay consistent:

  • Idempotent: how far the tool itself guarantees that a repeated run makes no further changes, rather than leaving it to the author.
  • Declarative: how much of the code states the desired result rather than the steps to reach it.
  • Query: how well code can look up existing infrastructure and current state (data sources, facts, inventories).
  • Execution: maturity of the engine: dependency ordering, preview before change, parallelism, and whether it keeps enforcing state after the run.
  • Modularity: native units of reuse with clear inputs and outputs, and a way to version and share them.
  • Documentation: how well the code and the tool document the infrastructure: typed and described inputs, readable previews, reference documentation.

Tools are rated as used in the course (for example Puppet and Chef masterless, without PuppetDB or Chef search). “SM index” is the title used on the source image.

The catalog includes tools that define, provision, configure, initialize, or orchestrate infrastructure from code and are covered in the course. Kubernetes is retained from the source slide. Image building with Packer, initialization with cloud-init, and orchestration with Bolt are included. Helm is included for packaging and releasing Kubernetes infrastructure. Supporting utilities, runtimes, general-purpose package managers, testing tools, and application services are excluded.

Edit the CSV in the repository to revise the catalog or add reviewed scores. Keep the scoring source and context with each row.
